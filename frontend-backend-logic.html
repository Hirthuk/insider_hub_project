API Configuration & Interceptor Implementation

API Configuration Setup

The api.js file handles all communication between frontend and backend with proper authentication and error handling.

1. Importing Axios

import axios from 'axios';

Pulls in the axios HTTP client library for making API calls with support for interceptors and request/response customization.

2. API Configuration

export const API_CONFIG = {
  BASE_URL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:8080',
  ENDPOINTS: {
    LOGIN: '/api/auth/login',
    LOGOUT: '/api/auth/logout',
    REFRESH_TOKEN: '/api/auth/refresh',
  }
};

BASE_URL

Uses Vite environment variable VITE_API_BASE_URL or defaults to localhost:8080

ENDPOINTS

Centralized endpoint definitions to avoid hardcoding URLs throughout the application

3. Creating Axios Instance

export const apiClient = axios.create({
  baseURL: API_CONFIG.BASE_URL,
  timeout: 10000, // 10 seconds timeout
  headers: {
    'Content-Type': 'application/json',
  },
});

Creates a custom Axios instance with default settings for consistent API communication.

Request Interceptor

What is the Config Object?

In Axios, every request starts as a configuration object built from:

  • Defaults set in axios.create({})
  • Arguments passed to .get(), .post(), etc.
  • Modifications made by request interceptors
// Example config object structure
{
  url: '/api/auth/login',
  baseURL: 'http://localhost:8080',
  method: 'post',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer <token>' // added by interceptor
  },
  data: { sapid: '...', password: '...' },
  timeout: 10000
}

Request Interceptor Implementation

apiClient.interceptors.request.use(
  (config) => {
    const token = localStorage.getItem('authToken');

    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }

    console.log('Making request to:', config.url);
    return config;
  },
  (error) => {
    console.error('Request error:', error);
    return Promise.reject(error);
  }
);

Request Flow:

You call: apiClient.get('/users')
Axios creates config: baseURL, url, method, headers
Request interceptor runs: Reads token, adds Authorization header, logs URL
Returns modified config: Axios uses updated config for HTTP request
Response/Error: Goes through response interceptors

Simple Analogy

Think of config as a pizza order slip:

  • Defaults: "Cheese Pizza" (baseURL, headers)
  • Your additions: "Extra Olives" (data, params)
  • Interceptor: Chef adding "free extra cheese for VIP customer" (Authorization header)
  • Final slip: Handed to kitchen (Axios core) to make the pizza (HTTP request)

Response Interceptor

apiClient.interceptors.response.use(
  (response) => {
    console.log('Response received:', response.status);
    return response;
  },
  (error) => {
    console.error('Response error:', error.response?.status, error.response?.data);

    if (error.response?.status === 401) {
      localStorage.removeItem('authToken');
      localStorage.removeItem('userRole');
      localStorage.removeItem('userSapId');
      localStorage.removeItem('isAuthenticated');

      if (window.location.pathname !== '/login') {
        window.location.href = '/login';
      }
    }

    return Promise.reject(error);
  }
);

Response Handling:

Success Response: Logs HTTP status, passes response to calling code
Error Response: Logs status code and error data from server
401 Unauthorized: Clears authentication data from localStorage
Auto Redirect: Redirects to login page (unless already there)
Error Propagation: Uses Promise.reject() to pass error to calling code

Understanding Promise.reject()

What Promise.reject(error) does:

In JavaScript, Promises represent async operations. Promise.reject(error) creates a failed Promise with the given error reason.

Why it's used in Axios interceptors:

// Without Promise.reject - error gets swallowed
(error) => {
  console.error('Request error:', error);
  // No return - error disappears!
}

// With Promise.reject - error propagates correctly
(error) => {
  console.error('Request error:', error);
  return Promise.reject(error); // Error reaches .catch()
}

Flow Example:

API Call: apiClient.get('/users').then(...).catch(...)
Request Fails: Error handler in interceptor runs
Promise.reject(): Returns rejected Promise with error
.catch() Triggered: Your calling code's .catch() receives the error

Analogy

throw error (sync) = Promise.reject(error) (async)

Without returning Promise.reject(), Axios thinks "oh, I got something back, maybe it's fine" and your .catch() won't trigger properly.

Interceptor Function Structure

apiClient.interceptors.request.use() expects two arguments:

apiClient.interceptors.request.use(
  requestSuccessHandler, // runs before request is sent
  requestErrorHandler    // runs if request config building fails
);

Success Handler

(config) => { ... } - Receives Axios config object, modifies it, and returns it

Error Handler

(error) => { ... } - Handles errors in request configuration and returns Promise.reject()

Critical Point

If you don't return config in the success handler, Axios won't know how to proceed and the request will never be sent!

Summary

What's Happening:

Setup: Define reusable apiClient with base URL, headers, and timeout
Before Request: Check for authToken in localStorage and attach to Authorization header
After Response: Handle success (return data) or error (clear auth data on 401, redirect to login)

Security Benefits

  • Automatic Authentication: JWT tokens attached to every request
  • Session Management: Automatic logout on token expiry
  • Error Handling: Centralized error handling and logging
  • Consistent Headers: Proper content-type and authorization headers
